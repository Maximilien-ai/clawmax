# 1.9.9 RC Manual Validation

> Archived outcome: `1.9.9-test-rc6` was promoted as `v1.9.9` on July 21, 2026. Unchecked items remain historical evidence or future regression coverage, not active release gates.

Use this checklist cumulatively for `1.9.9` release candidates. Mark items as they are confirmed and carry only incomplete or regressed items into the next RC.

## RC6 Preconditions

- [ ] Set `CLAWMAX_SECRET_MASTER_KEY` to a stable random value of at least 32 characters and restart ClawMax.
- [ ] Use a non-production sentinel value. Do not use a normal Google password or any primary-account credential.
- [ ] Assign the packaged `clawmax-secret-test` skill to one test agent.
- [ ] Keep a second agent without a grant for the authorization-negative test.

## Release Identity And Existing Fixes

- [ ] Dashboard and `/api/system` report `1.9.9-test-rc6`.
- [ ] OpenClaw remains on the expected `v2026.6.11` baseline.
- [ ] On iPhone Safari, open a workflow with a long run form and confirm `Run Workflow` remains visible and tappable while the form scrolls.
- [ ] Repeat the workflow dialog check on desktop.

## RC4 Feedback Regression: Gmail Chat And OpenAI Models

- [ ] Open an existing agent saved with primary model `openai/gpt-5` and backup model `openai/gpt-4.1-mini`; confirm chat executes through the supported `openai/gpt-5.4-mini` runtime mapping without editing or redeploying the agent.
- [ ] Open the agent editor and confirm new OpenAI selections offer runtime-supported IDs such as `openai/gpt-5.4`, `openai/gpt-5.4-mini`, and `openai/gpt-5.4-nano`, not the unsupported `openai/gpt-5` alias.
- [ ] Start a request that uses tools for longer than 15 seconds; confirm chat reports elapsed work time and explains that tool-enabled requests can take up to three minutes instead of remaining at `Agent is typing...`.
- [ ] Force or observe an incomplete tool turn; confirm chat warns that tools may already have executed, recommends verifying results, and exits the active working state.
- [ ] Store a non-production Gmail-shaped test key in Workspace Keys; confirm the browser-local warning says it cannot be referenced by name in agent chat and that a stored password alone does not grant mailbox access.
- [ ] Confirm **Agent & Skill Access** opens the broker tab and **Find Email Skills** opens Skills.
- [ ] Confirm a Gmail request without an assigned/configured Gmail-capable skill fails with setup guidance rather than implying that a browser-local password is available.

## Encrypted Workspace Secret

- [ ] Open **Keys & Secrets → Agent Skill Secret Access** and confirm `Encrypted broker ready` appears.
- [ ] Save `CLAWMAX_TEST_SECRET` with a unique non-production sentinel value.
- [ ] Confirm the inventory shows only the key name and masked preview.
- [ ] Refresh the page and confirm the masked entry remains.
- [ ] Restart the container and confirm the masked entry remains readable with the same master key.
- [ ] Restart once with a different/missing master key and confirm the broker fails closed; restore the original key afterward.

## Explicit Grant And Broker Test

- [ ] Authorize `CLAWMAX_TEST_SECRET` for the assigned `clawmax-secret-test` skill and test agent.
- [ ] Confirm the active grant lists agent, skill, key name, and fingerprint, but no raw value.
- [ ] Click **Test Access** and confirm `secretAvailable: true` plus a one-way fingerprint.
- [ ] Confirm the raw sentinel does not appear in the success message, browser console, activity, or dashboard logs.
- [ ] Attempt to authorize the skill for an agent where it is not assigned and confirm the request is rejected.
- [ ] Attempt an undeclared or wildcard key and confirm the request is rejected.

## Agent, Group, And Workflow Execution

- [ ] Start a new direct chat with the granted agent and ask it to verify brokered secret access. It should run `clawmax-skill-run clawmax-secret-test check` and report availability/fingerprint only.
- [ ] Ask the agent to print, list, or echo the secret. Confirm it refuses or returns no raw secret.
- [ ] Ask the ungranted agent to run the same command. Confirm it receives actionable authorization guidance and no value.
- [ ] Run a group chat containing the granted agent and request the same verification.
- [ ] Run a workflow containing the granted agent and request the same verification.
- [ ] Confirm neither group history nor workflow execution history contains the sentinel.

## Revocation And Persistence

- [ ] Revoke the active grant.
- [ ] Start a new direct chat/workflow execution and confirm the next broker invocation is denied.
- [ ] Reauthorize, restart the container, and confirm the grant and authorized action persist.
- [ ] Remove the skill assignment and confirm the existing grant no longer authorizes execution.

## Export And Log Safety

- [ ] Export the workspace and confirm the ZIP contains no `SYSTEM/.clawmax` directory.
- [ ] Confirm the ZIP contains no `SYSTEM/integrations.secrets.json` file.
- [ ] Search the exported ZIP, dashboard logs, OpenClaw logs, workspace Markdown, chat history, and workflow history for the sentinel; expect zero matches.
- [ ] Delete `CLAWMAX_TEST_SECRET` and confirm subsequent execution reports the missing secret without exposing prior content.

## OpenRouter Release Gate

- [ ] With a real OpenRouter developer key, run direct chat locally.
- [ ] Run group chat and a workflow through OpenRouter locally.
- [ ] Repeat direct chat and workflow in the RC6 container/on-prem environment.
- [ ] Confirm invalid keys and unavailable models return provider-specific guidance.
- [ ] Confirm an OpenAI-compatible/LM Studio base URL cannot capture OpenRouter traffic.

## xAI / Grok Release Gate

- [ ] Add a real xAI developer key in Workspaces Integrations / BYOK and confirm Check Key succeeds.
- [ ] Confirm xAI appears as a separate hosted provider and Keys & Secrets classifies `XAI_API_KEY` as an LLM key.
- [ ] Refresh models and confirm compatible native `xai/...` models appear, including `xai/grok-3` and `xai/grok-4.3` when available.
- [ ] Confirm `xai/grok-4.5` is not offered on the pinned OpenClaw `v2026.6.11` runtime.
- [ ] Run direct chat, group chat, and a workflow through xAI locally.
- [ ] Repeat direct chat and workflow in the RC6 container/on-prem environment.
- [ ] Confirm invalid xAI keys, missing credits, and unavailable models return provider-specific guidance.
- [ ] Confirm configured OpenAI, OpenRouter, and OpenAI-compatible/LM Studio credentials cannot capture xAI traffic.

## Mobile Keys And Secrets

- [ ] Confirm Agent & Skill Access, Workspace Keys, Global Keys, and Partners are separate tabs and unrelated sections are hidden.
- [ ] Switch tabs, refresh the page, and confirm the last selected tab is restored.
- [ ] On narrow screens, confirm the tab row scrolls horizontally while the page itself does not overflow.
- [ ] Confirm LLM, Partners, Infra, and Other remain filter pills inside Workspace and Global rather than acting as page tabs.
- [ ] On iPhone Safari, confirm the broker status, secret form, authorization form, active grant, Test Access, and Revoke controls fit without horizontal overflow.
- [ ] Confirm the password field does not reveal the secret and controls remain usable with the software keyboard open.
