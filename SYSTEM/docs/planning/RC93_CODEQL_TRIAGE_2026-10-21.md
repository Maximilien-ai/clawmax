## Acceptance for RC93

- Trace actual input authority for each reported sink, including local and cloud deployment modes, and record whether an untrusted actor can reach it.
- Fix any reachable path or command execution hazard with focused error, authorization, persistence, and regression tests. Use a bounded CodeQL dismissal with evidence only for findings proven inapplicable.
- For any session-key change, test old-to-new lookup, collision behavior, and restart persistence with existing stored sessions.
- Re-run focused tests, TypeScript, CodeQL PR analysis, and the full RC suite before RC93 image publication. Record the residual open alert count by severity and owner.

This triage does not change the published RC92 image or authorize a production rollout.

## October 22 follow-up: source and runtime evidence

Dashboard source checkpoint `aa619f61` has a successful [main CodeQL analysis](https://github.com/Maximilien-ai/clawmax/actions/runs/39745666495) at its preceding product commit `e2f23bb8`; this is scan execution evidence, not an alert disposition. The seven named alerts remain open. The repository-wide query on October 22 returned 673 open alerts: 17 critical, 649 high, and 7 medium. Those counts include older findings outside this seven-alert review and are not a complete security audit.

- **610–612, command execution:** `normalizeAgentRuntime` accepts only `openclaw`, `claude`, or `droid`; cloud deployment rejects the latter two. The local executable is resolved from operator process environment (`CLAUDE_BIN`, `DROID_BIN`, `PATH`, or `HOME`), not a request parameter. The three sinks use `execFileSync`, `spawn`, and `execFile` with argument arrays and no `shell` option. User messages and model names can become arguments, but cannot replace the executable or become shell syntax. Existing `agent-runtime.test.ts` covers override/PATH/HOME precedence, invalid overrides, and execution; `integrations.test.ts` covers cloud rejection. This bounds the reported shell injection route to an operator who can already set the dashboard process environment or replace an installed executable. We have not dismissed the alerts or claimed that an operator-controlled executable is safe to run.
- **69, executable lookup:** `which` receives the fixed allowlisted binary name as its argument. Its own resolution uses the dashboard process PATH; that is an operator-controlled deployment input in local mode. Cloud mode returns `null` before this lookup. There is no request-to-PATH assignment in this path. A compromised PATH or installed binary remains an operator environment compromise, not tenant path traversal.
- **706–707, legacy transcript path:** `readPersistedChatTranscript` rejects session IDs outside `[A-Za-z0-9_-]+`; `readNativeChatTranscript` reaches `databasePath`, which applies the same allowlist to agent IDs, before the legacy JSONL path is built. Production callers supply `home` from `process.env.HOME`, while request agent IDs are validated by routes. SQLite session IDs are bound parameters. `native-chat-history.test.ts` covers agent and session traversal rejection and reopened history. The review did not establish whether a local actor with write access can plant symlinks inside the operator's `.openclaw` store; this remains outside a remote request path.
- **579, session identity:** The SHA-1 output was not a secret, credential, or integrity check, but its eight-hex-character suffix had a **real identity collision risk**. A deterministic local reproduction using a common long prefix and `openai/gpt-5` found `group-demo-window-with-a-very-long-common-prefix-1596` and `...-27592` both mapping to `group-demo-window-with-a-very-long-comm-0e696564`. Commit `6faee7a7` uses a 16-character SHA-256 suffix for new long session IDs and continues existing server-generated dashboard chats when their old native or JSONL session is present. Focused tests verify the collision pair differs, both persisted store formats remain selectable on a new lookup, and a new chat uses the wider suffix. [CodeQL on that commit](https://github.com/Maximilien-ai/clawmax/actions/runs/39748539935) completed successfully and marked alert 579 **fixed**, without dismissal. Arbitrary caller-supplied long session IDs are not migrated to a legacy hash because the old 32-bit key cannot prove which original input owned it; prior transcripts remain in their stores.

The October 22 full isolated integration/validation/coverage run completed 537/538 checks. Its only reported failure was the chat composer harness expecting a stale `12 assertions passed` line while the test printed its new success text; the test itself passed. Commit `aa619f61` aligns the 39-assertion output and harness. A second run passed 538/538, but code changed while it was running, so a clean final run is in progress. The restarted local dashboard's `/api/system` and rendered top-right label both show `2.0.0-test-rc93`.

The six named command/path alerts (610–612, 69, 706–707) remained open after the `6faee7a7` scan. The source trace above establishes no shell interpolation or remote control of the executable path. It does **not** fully settle whether a CLI parser can treat a prompt beginning with an option prefix as a flag, or whether a local actor can plant symlinks in the operator-owned transcript store. These require a separate bounded review before promotion beyond internal RC testing; no dismissal or security-cleared claim is made here.
